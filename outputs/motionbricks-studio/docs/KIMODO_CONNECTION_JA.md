# Kimodoを任意追加してStudioから起動する

Studioの「Kimodo → Kimodo連携」を開きます。選ぶのはlauncher.pyが入っているkimodo-studioフォルダーです。ファイル単体や公式ソースのsourceフォルダーは指定しません。既定の場所を検出していればボタンで選べます。「環境を診断」でPython／依存パッケージ／CUDAを確認し、起動アプリを開きます。診断はバックグラウンドで最大30秒です。

制作の流れは、Kimodoで生成・経路調整・動作確認 → NPZ保存 → Studioメインの「モーション・ポーズ・ライブラリ」で取り込み、に統一しました。連携画面には結果フォルダーを開くボタンを残し、重複取り込みとStudioからの直接生成は削除しました。生成済みのファイルは保持します。単独制作アプリのKimodoや旧ジョブの結果フォルダーを削除する更新ではありません。

未導入時には、Kimodo導入 → Hugging Faceアカウント → Llama 3の規約同意・申請 → 承認後の認証 → モデル取得 → Kimodoで生成、の順序を表示します。実際のインストールボタン・導入支援は次のKimodo側更新で対応予定で、今回のMotionBricksのみの更新では追加していません。

NPZは既存のSOMA77変換で全フレームを保持します。取り込むと選択ターゲットを変更するため、残したいターゲットは先に複製してください。非ダンスの全尺再生初期値はOFFです。利用者別パスはuser_data/kimodo-connection.jsonに保存し、認証・モデルはKimodo側で別管理します。環境診断だけでモデルアクセス承認や生成成功を保証するものではありません。

現在の画面と5言語の図は内蔵説明書で確認できます。過去の生成ジョブ試験記録JSONは履歴資料として保持しますが、現行Studioの提供機能の説明ではありません。
